## 3. 每周协作节奏

- 每日：成员在任务看板更新“完成、下一步、阻塞”，阻塞超过半天立即找接口负责人。
- 每周一：检查故事点与依赖，调整任务，不让某人长期承担超额工作。
- 每周五：集成演示、记录缺陷、冻结下周要用的接口变更。
- 合并前：至少一人评审；涉及接口或数据库字段时，对应前后端双方确认。

## 4. 依赖与风险

| 风险 | 影响 | 处理方式 |
| --- | --- | --- |
| 前后端接口理解不一致 | 联调延期 | 第一周冻结请求/响应示例，变更走 PR |
| 视频上传与演示环境不稳定 | 发布功能受阻 | 先完成图片和文本主流程，再做视频短文件；准备本地演示素材 |
| 七人并行改同一模块 | 冲突增加 | 按上表设主负责人，跨模块通过 PR 和接口契约协作 |
| 过早投入大模型/好友 | 必做功能延期 | 加分项只在第 3 周主流程通过后开始 |
| 组内完成目标延误 | 压缩正式提交缓冲 | 第 3 周开始每周检查剩余任务，必要时停止加分项 |
