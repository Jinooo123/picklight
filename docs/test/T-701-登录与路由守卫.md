状态：前端草稿已实现，单元测试及浏览器模拟响应验证通过；真实后端联调尚未执行。当前不得关闭 Issue，也不把以下模拟结果填写为真实接口验收。

## 实现依据与范围

- 使用已合并的 T-702 请求入口及 T-008 主题。
- 登录字段暂依 [T-003 PR #103](https://github.com/Jinooo123/picklight/pull/103) 第 8 节联合评审稿：`POST /api/v1/auth/login` 返回 `code: 0`、`data.token/user`；`GET /api/v1/me` 返回当前用户。该稿尚未冻结。
- 只允许服务端返回 `role: ADMIN` 且 `status: ACTIVE` 的账号进入。不能靠本地 token 字符串、缓存角色或解析未验证的 JWT 认定管理员。
- token 使用现有 `localStorage.token`，刷新后通过 `/me` 重新验证；密码不保存并在提交结束后清空。登录只去除用户名首尾空白，保留原密码。
- 成功后返回原内页，保留查询参数和片段；允许的回跳页是看板、用户管理、内容管理。外部地址及无效目标回退 `/dashboard`。
- `/me` 的 401 由守卫处理，避免全局重定向丢失尚未进入的目标页；其余接口保留全局 401 清理及来源回跳。临时故障不当作 token 失效，支持重试身份验证。

真实接口未就绪时页面会显示请求失败，不提供假 token 或演示账号绕过。样例响应仅存在于验证代码中。

## 浏览器验证（模拟服务端）

Chrome 加载实际 Vite 生产构建，用浏览器路由拦截提供上述评审稿响应，不连接真实后端。

| 场景 | 结果 |
| --- | --- |
| 匿名访问 `/users?page=2#results` | 跳登录，来源完整保留 |
| 空表单提交 | 提示输入账号密码，不发请求 |
| 普通用户、错密、禁用、业务错误、缺 token | 显示可读错误，不持久化返回 token，密码清空 |
| 连续两次提交 | 仅发出一个登录请求 |
| 管理员成功登录 | 请求不带旧 token，回原页，密码不进入本地存储 |
| 刷新受保护页 | 带 Bearer token 请求 `/me`，核验后显示内页 |
| 假 token、缓存伪造 ADMIN 但 `/me` 返回 USER | 拒绝进入并清理 token |
| `/me` 临时返回 503，恢复后重试 | 保留 token，重试后回到目标页 |
| 受保护请求 401、退出 | 清理会话并回登录，401 保留来源 |
| 来源为外部 URL | 留在当前站点并进入看板 |

生产构建通过；截图已核对，未发现页面脚本错误。截图为模拟响应验证证据，不代表真实管理员账号已签发。

本环境用直接导入 `vite.config.js` 后调用 Vite `build({ ...config, configFile: false })` 的方式完成构建，以避开本机配置打包时的父目录访问限制；源码与配置和标准 `npm run build` 相同。
