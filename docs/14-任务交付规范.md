# 任务交付规范

本规范规定「一个任务从领取到算完成」的完整动作。七个人按同一套做，代码才合得进、查得到、回得去。

**一句话**：开分支写代码只是第一步，**PR 合并进 main 才算完成**。

## 1. 什么叫"做完了"（Definition of Done）

五项缺一不可，缺任何一项都只能算"写了一半"：

- [ ] 代码在 `main` 上（PR 已合并，不是只推了分支）
- [ ] PR 描述里写了 `Closes #编号`，对应的 Issue 已自动关闭
- [ ] Issue 里的验收标准逐条勾选完毕
- [ ] 分支已删除（远端 + 本地）
- [ ] 自己本地 `git pull` 过，工作区干净

> 常见的自欺：把代码推到 `feat/xxx` 分支就说"做完了"。别人看不到、CI 不检查、Issue 不关闭、下一个人没法在此基础上写——**这在我们的规范里不算完成**。

## 2. 标准流程（七步）

### 第 1 步：领任务，读验收标准

打开 Issues → 按里程碑筛选（本周是 `M0 初步版本`）→ 找自己名字的任务。

点进去**先读「验收标准」**，那里写了什么算做完。不要跳过直接写代码。

### 第 2 步：同步 main，开分支

```bash
git switch main
git pull
git switch -c feat/T-201-media-picker
```

分支命名规则：`类型/任务号-两三个英文词`

| 类型 | 用途 | 例子 |
| --- | --- | --- |
| `feat` | 新功能 | `feat/T-201-media-picker` |
| `fix` | 修缺陷 | `fix/T-305-rating-double-submit` |
| `docs` | 只改文档 | `docs/T-902-statistics-contract` |
| `chore` | 配置、依赖、脚本 | `chore/setup-ci` |

**一个分支只做一项任务。** 顺手改别的文件，评审时会被退回。

### 第 3 步：写代码，小步提交

```bash
git add -A
git commit -m "feat(T-201): 媒体选择与预览"
```

提交信息格式：`类型(T-任务号): 做了什么结果`

```text
feat(T-201): 媒体选择与预览
fix(T-305): 连点导致重复评分
docs: 补第 1 周会议记录
test(T-509): 补动态检索边界用例
```

括号里是任务号，冒号后写**结果**不是过程。写「更新代码」「修改一下」会被提交钩子拦下。

**每完成一小块就提交**，别攒一天。两小时提交一次，出问题能退回；攒一天提交，搞砸了只能重写。

### 第 4 步：推分支（不是推 main）

```bash
git push -u origin feat/T-201-media-picker
```

推完终端会打印一行 `Create a pull request ...` 的链接。**这一步只完成了上传，还没有 PR。**

如果报 `protected branch hook declined` 或 `GH006`，说明你推的是 `main`——改成推自己的分支。

### 第 5 步：开 PR（最容易漏的一步）

推完分支后，仓库首页顶部会出现黄色横幅 **Compare & pull request**，点它；或者直接打开：

```text
https://github.com/Jinooo123/picklight/compare/main...你的分支名?expand=1
```

填写：

- **标题**：与最后一次提交一致
- **描述**：第一行必须写 `Closes #编号`，然后按模板填"改了什么 / 怎么验证"

```text
Closes #21

## 改了什么
发布页支持选 9 张图或 1 个 60 秒内的视频，选择后可预览与删除。

## 怎么验证
1. 选 3 张图 → 预览缩略图正常，可单张删除
2. 选视频 → 提示时长上限，超过 60 秒被拒
3. 不选任何媒体直接发布 → 提示"请至少选择一张图片或一个视频"
```

- 右侧 **Reviewers** 可以不选（评审不强制），但推荐叫一个相关的人看一眼

点 **Create pull request**。

### 第 6 步：合并

1. 点 **Files changed** 扫一眼红绿，确认没有误提交的文件
2. 绿色按钮下拉 → **Squash and merge**（不要用普通 merge）
3. **Confirm squash and merge**
4. 出现 **Delete branch** 就点它

为什么用 squash：一个任务可能有五六个"改拼写""再改一下"的碎提交，squash 会把它们压成一条干净记录，历史图不会变成蜘蛛网。

### 第 7 步：本地收尾

```bash
git switch main
git pull
git branch -D feat/T-201-media-picker
```

用 `-D` 不是 `-d`：squash 合并会生成新提交，你本地那个原始提交在 Git 看来"没被合并过"，用小写会报错拒绝。内容其实已经在 main 上了。

然后回 Issue：勾完验收标准 → 确认状态是 `Closed`（写了 `Closes #编号` 会自动关）。

## 3. PR 评审（建议但非强制）

**看四件事**：

1. 有没有越权：普通用户能不能改别人的数据、调管理接口
2. 异常路径：参数为空、超长、不存在、未登录，有没有处理
3. 接口字段：有没有偷偷改字段名或结构，改了有没有同步 `docs/08-api-contract.md`
4. 有没有误提交：密码、密钥、`.env`、上传的图片视频、`node_modules`

**怎么提意见**：在 Files changed 里点行号左侧的 `+`，写 comment。用「必须改」和「建议」区分，别只说"这里不太好"。

评审用 `Approve` 或 `Request changes`。**不要直接改别人的分支**，除非对方明确说"你帮我改"。

## 4. 常见错误与处理

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| PR 列表里找不到自己 | 只推了分支，没点 Create pull request | 首页点黄色横幅，或开 compare 链接 |
| `GH006: Protected branch update failed` | 在往 `main` 推 | 改成推自己的分支，再开 PR |
| 合并后 Issue 没关闭 | PR 描述里没写 `Closes #编号`，或写成了「关闭 #12」 | 手动关闭 Issue，下次用英文关键字 |
| 本地 `git branch -d` 报 not fully merged | squash 合并后原始提交不在 main 历史 | 用 `git branch -D` |
| 合并后本地代码还是旧的 | 合并发生在远端 | `git switch main && git pull` |
| PR 显示 This branch has conflicts | 两人改了同一处 | 本地 `git pull origin main` 解决后重推，别在网页上点 Resolve |
| `Connection reset` / `Connection timed out` | 校园网抖动 | 重试 2-3 次；仍不行改用 HTTPS + token 临时推 |
| 推完发现漏了文件 | 忘了 `git add` | 补一个 commit 再 push，PR 会自动带上，不用重开 |

## 5. 时间要求

- **当天开的分支，三天内必须合并**。拖久了必冲突。
- **每天 22:00** 群里发三行：昨天完成 / 今天做 / 卡在哪。
- **被阻塞超过半天**立即在群里报任务号，不要自己扛到周五。
- **周五晚**演示可运行版本，不看文档看功能。

## 6. 公共文件不要多人改

| 文件 | 归谁改 |
| --- | --- |
| `apps/miniprogram/pages.json`、`manifest.json` | 欧阳文锦 |
| `apps/admin/package.json`、`src/router/index.js`、`vite.config.js` | 黄佳佳 |
| `services/api/pom.xml`、`application.yml` | 梁文博 |
| `docs/06-task-breakdown.md`、`docs/tasks.csv` | 欧阳文锦（改 `scripts/gen_task_docs.py` 后重新生成） |
| `.github/`、`.githooks/` | 欧阳文锦 |

要改别人的公共文件，先在群里说一声，不要直接改。

## 7. 一分钟速查卡

```text
1 看 Issue 验收标准
2 git switch main && git pull
3 git switch -c feat/T-xxx-简述
4 写代码 → git add -A → git commit -m "feat(T-xxx): 说明"
5 git push -u origin feat/T-xxx-简述
6 网页点 Compare & pull request → 描述写 Closes #编号 → Create
7 Squash and merge → Delete branch
8 git switch main && git pull → git branch -D 分支
9 Issue 勾完验收标准，确认已关闭
```

**记不住就记这一句：推分支不算完，PR 合了才算完。**
