# 从 0 到 1：第一次完成任务

给从没碰过 Git 的人。看完这一篇，能独立走完「领任务 → 写代码 → 提 PR → 合并」。命令里 `<方括号>` 换成你自己的内容。

## 0. 三个词先搞懂

| 词 | 人话 | 谁动它 |
| --- | --- | --- |
| 仓库 | 放代码的地方，在 GitHub 上 | 大家共用 |
| 分支 | 你自己的一份草稿 | 只有你 |
| 合并 | 把草稿并进正式版 | 在网页上点按钮 |

你永远在**自己的分支**上写，写完推到 GitHub，开一个 PR（合并请求），网页上点合并。你**不直接改** main。

## 1. 一次性准备（只做一次）

```bash
# 生成钥匙，一路回车
ssh-keygen -t ed25519 -C "你的邮箱"

# 看公钥，把输出整行粘到 https://github.com/settings/keys
cat ~/.ssh/id_ed25519.pub

# 建配置文件 C:\Users\你的用户名\.ssh\config，写四行：
#   Host github.com
#     HostName ssh.github.com
#     Port 443
#     User git

# 验证：出现 Hi <用户名>! 就成
ssh -T git@github.com

# 下载代码
git clone git@github.com:Jinooo123/picklight.git
cd picklight

# 启用提交钩子（Windows）
powershell -ExecutionPolicy Bypass -File scripts/setup-dev.ps1
```

## 2. 领一个任务

打开 https://github.com/Jinooo123/picklight/issues ，左边 Milestones 选当前周。标题 `[T-101] 登录页`，编号对应到人（分工见 `docs/06-task-breakdown.md`）。点进去读「验收标准」，**照着一项项做**。

## 3. 每天开工（四步，抄就行）

```bash
git switch main && git pull                 # 1 拿最新
git switch -c feat/<T-101>-<login-page>     # 2 开自己的分支
# ……写代码……
git add -A && git commit -m "feat(T-101): 登录页 UI 与表单校验"   # 3 存一下
git push -u origin feat/<T-101>-<login-page>                      # 4 传到网上
```

- 分支名：`feat/<任务号>-<两个英文词>`，如 `feat/T-101-login-page`
- 提交信息：`feat(T-101): 做了什么`，格式错会被钩子拦下

## 4. 开 PR 并合并（在网页上）

1. push 后打开仓库页，点顶部黄色 **Compare & pull request**
2. 标题同提交信息；描述写三行：

```text
Closes #<Issue 编号>

## 改了什么
<一句话>

## 怎么验证
<怎么测的>
```

3. 点 **Create pull request**，然后 **Files changed** 扫一眼红绿
4. 绿色 **Squash and merge** → **Confirm** → **Delete branch**
5. 回本地同步：

```bash
git switch main && git pull
git branch -D feat/<T-101>-<login-page>
```

`Closes #编号` 会让合并后 Issue 自动关闭。

## 5. 卡住怎么办

按顺序试：看 `docs/11` 第 8 节常见报错 → 把报错原文发群里 → 还不行 @ 欧阳文锦。**报错别只发“跑不起来”**，要贴命令、贴完整报错、贴你改的那段代码。

## 6. 每天收尾（22:00 群里三行）

```text
昨天：xxx
今天：xxx
卡点：无 / 卡在 xxx，需要 xxx
```

---

一句话记住全流程：**拉最新 → 开分支 → 写 → 提交 → 推送 → 网页合并 → 回本地拉。**
